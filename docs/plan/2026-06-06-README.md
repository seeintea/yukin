# Yukin Agent — 全原生分步实施计划

> 创建日期: 2026-06-06
> 目标: 把空白 Tauri 2 + React 19 + TS 脚手架做成完整桌面 agent
>
> **架构原则**: Agent loop、LLM HTTP 调用、tool dispatch **全部在 Rust**。
> 前端只负责: 用户输入收集、事件流渲染、设置管理。
> API Key **永不出 Rust** 进程。

---

## 核心架构

```
┌────────────── React renderer (薄壳) ──────────────┐
│ ChatPage: chat_send(invoke) → Channel<AgentEvent>  │
│          流式渲染 text/tool-call/tool-result       │
│ Settings: workspace / key / provider 表单          │
│ Sessions: 列表 + 切换                              │
│ 无: ai / @ai-sdk/* / zustand persist / tools.ts   │
└────────────────────│────────────────────────────────┘
                     │ invoke + Channel<AgentEvent>
┌────────────────────▼ Rust (重) ────────────────────┐
│ commands/agent.rs                                  │
│   chat_send(session_id, msg) → run_id              │
│   chat_abort(run_id)                               │
│                                                    │
│ agent/loop.rs                                      │
│   async fn run_agent(messages, tools, sender) {    │
│     loop {                                         │
│       LLM stream → emit TextDelta | ToolCall       │
│       on ToolCall → registry.execute → feed back   │
│       on stop / max_steps → break                  │
│     }                                              │
│   }                                                │
│                                                    │
│ llm/anthropic.rs                                   │
│   reqwest POST /v1/messages → SSE 解析             │
│   emit TextDelta / ToolUse / MessageStop           │
│                                                    │
│ tools/                                             │
│   mod.rs → registry: Vec<Box<dyn Tool>>            │
│   fs.rs, memory.rs, shell.rs, http.rs              │
│   trait Tool { name, description, input_schema,    │
│                execute(args: Value) -> ToolResult } │
└────────────────────────────────────────────────────┘
```

## 关键决策(已确认)

| 维度 | 选择 |
|------|------|
| Agent 架构 | **全 Rust**(前端只做 UI) |
| LLM 调用 | 自手 reqwest + SSE 解析 |
| Tool schema | `schemars` derive + `serde_json::Value` |
| v1 provider | **仅 Anthropic Claude** |
| API Key 存储 | OS Keychain via `keyring` |
| Memory 存储 | SQLite (`sqlx` + FTS5) |
| 文件作用域 | dialog 选工作目录 + `safe_join` |
| 流式传输 | Tauri 2 `Channel<AgentEvent>` |
| 取消 | `CancellationToken` per run_id |
| UI 方案 | Tailwind v4 + shadcn/ui |
| v1 tools | file CRUD / memory r-w / shell exec / http fetch |

## 跨阶段约定

### 统一错误类型
```rust
#[derive(thiserror::Error, Debug, Serialize)]
#[serde(tag = "code", content = "message")]
pub enum AppError { NoWorkspace, PathEscape(String), Io(…), Db(…), Keyring(…), Shell(String), Http(…), Llm(String), Cancelled }
```

### 路径安全(任何 fs 命令必走)
```rust
pub fn safe_join(root: &Path, user: &str) -> AppResult<PathBuf>
// path_clean + canonicalize + .starts_with(prefix) 检查
```

### Channel 事件类型(前端唯一关心的数据流)
```rust
#[derive(Clone, Serialize)]
#[serde(tag = "type")]
pub enum AgentEvent {
    TextDelta { delta: String },
    TextDone,
    ToolCall { id: String, name: String, input: serde_json::Value },
    ToolResult { id: String, result: serde_json::Value },
    Error { message: String },
    Finish { usage: serde_json::Value },
}
```

### API Key 约束
- 永不出 Rust 进程
- `chat_send` 内部: `key_get(provider)` → 构造 Authorization header → 用完释放

## 多 Provider 扩展预留

```rust
#[async_trait]
pub trait LlmProvider: Send + Sync {
    fn name(&self) -> &str;
    async fn stream_chat(
        &self,
        messages: &[ChatMessage],
        tools: &ToolRegistry,
        api_key: &str,
        model: &str,
        sender: tokio::sync::mpsc::UnboundedSender<LlmEvent>,
        cancel: CancellationToken,
    ) -> AppResult<()>;
}
```
