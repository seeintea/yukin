# Yukin 通用桌面助手 V1 开发计划

> 创建时间：2026-08-13 13:34:30（Asia/Shanghai）  
> 产品定位：以本地文件处理、桌面能力、提醒和自然语言交互为核心的通用桌面助手。  
> 技术约束：不绑定前端框架，不绑定 Rust 具体库；Rust 是业务状态与安全边界的权威来源。

## 1. V1 交付目标

用户能够通过自然语言完成下面的完整链路：

1. 与助手进行可恢复的流式对话。
2. 搜索、筛选、读取和打开本地文件。
3. 读取或写入剪贴板。
4. 在预览并确认后创建、复制、移动、重命名文件，以及将文件移入回收站。
5. 创建一次性或周期提醒，并在到期时收到系统通知。
6. 查看 Agent 正在执行的步骤、工具调用、授权请求和最终结果。
7. 在应用重启后恢复会话、提醒和可恢复的任务状态。

V1 不包含：任意 Shell 执行、支付或发消息、任意应用 UI 自动化、插件市场、多 Agent、云同步、长期记忆、无人值守的高风险操作。

## 2. 职责边界

### Rust 侧

- Agent Runtime、模型请求与流式解析。
- 会话、消息、Run、工具调用、授权和提醒的持久化。
- 文件系统、剪贴板、通知、托盘、快捷键等系统能力。
- 路径、权限、风险和授权校验。
- 后台任务、取消、超时、重试、日志和审计。
- 向 JS 暴露 Commands，并通过 Events 推送状态。

### JS 侧

- 页面布局、导航、对话和设置界面。
- 流式内容、任务步骤、工具结果和错误展示。
- 文件选择、操作预览、授权确认和冲突处理交互。
- 提醒管理、任务中心、快捷输入等用户体验。
- 只保存临时界面状态，不作为业务数据的最终来源。

### 强制规则

1. API Key 不进入 JS 的长期存储，也不向 JS 返回明文。
2. 所有系统副作用由 Rust 执行。
3. 是否需要授权由 Rust 判断，JS 只提交用户决定。
4. 授权必须绑定 `approvalId + runId + toolCallId + 参数摘要`，不得只传 `approved: true`。
5. 前端丢失事件后通过快照接口恢复，不自行推断 Run 状态。
6. 文件删除默认进入系统回收站，V1 不提供永久删除。

## 3. 共享协议先行

在实现具体页面和工具前，先确定带版本号的共享数据结构。建议统一使用字符串 ID、ISO 8601 时间和可序列化错误对象。

### 核心类型

- `Conversation`
- `Message`
- `Run` / `RunStatus`
- `RunStep`
- `ToolCall` / `ToolResult`
- `ApprovalRequest` / `ApprovalDecision`
- `Schedule`
- `Artifact`
- `AppError`

`RunStatus` 至少包含：

```text
pending
running
waiting_approval
waiting_user_input
scheduled
completed
failed
cancelled
```

### JS → Rust Commands

```text
conversation_create
conversation_list
conversation_get
conversation_rename
conversation_delete

message_send
run_get_snapshot
run_cancel
run_retry
approval_resolve

file_select
file_search
file_preview_operation

schedule_create
schedule_list
schedule_update
schedule_delete

settings_get
settings_update
model_test_connection
diagnostics_export
```

### Rust → JS Events

```text
run_started
run_status_changed
run_output_delta
run_plan_updated
run_waiting_approval
run_waiting_user_input
run_completed
run_failed
run_cancelled

tool_started
tool_progress
tool_completed
tool_failed

schedule_triggered
notification_clicked
```

每个事件至少包含 `schemaVersion`、`eventId`、`timestamp`，任务事件还应包含 `conversationId` 和 `runId`。

## 4. 执行阶段

## 阶段 0：协议与工程基础

**目标：** 建立两侧可以独立开发的稳定骨架。

### Rust 侧任务

- [ ] 建立 `commands`、`events`、`storage`、`agent`、`tools`、`approval`、`schedules`、`security`、`diagnostics` 模块边界。
- [ ] 定义核心共享类型、ID 规则、时间格式和 `schemaVersion`。
- [ ] 定义统一 `AppError`，至少区分校验、权限、模型、存储、系统、取消和内部错误。
- [ ] 实现应用配置加载、保存和配置版本迁移入口。
- [ ] 实现结构化日志、日志脱敏、轮转和诊断导出入口。
- [ ] 建立本地数据存储与迁移机制。
- [ ] 提供 `app_get_bootstrap`，一次返回版本、功能开关和当前配置摘要。
- [ ] 给所有 Tauri Command 增加参数校验和稳定的返回结构。

### JS 侧任务

- [ ] 建立页面、组件、状态、后端客户端、事件监听器和共享类型目录。
- [ ] 封装统一的 Command 调用层和错误转换层。
- [ ] 封装统一的 Event 订阅、取消订阅和重复事件过滤机制。
- [ ] 完成主窗口骨架：侧栏、主内容区、设置入口和全局错误提示。
- [ ] 实现启动加载、不可恢复错误和空状态界面。
- [ ] 约定 UI 临时状态与 Rust 持久状态的边界。

### 测试与验收

- [ ] Rust 核心类型可序列化/反序列化测试。
- [ ] Command 参数非法时返回稳定错误，不发生崩溃。
- [ ] JS 能显示 Rust 返回的结构化错误。
- [ ] 应用启动、关闭、重启后配置和数据库仍可正常读取。
- [ ] 日志中不出现 API Key 等敏感字段。

**出口条件：** 两侧只依赖协议即可并行工作；应用启动无示例 `greet` 业务残留；基础检查和构建通过。

## 阶段 1：模型与会话闭环

**目标：** 用户可以配置模型并进行可持久化、可取消的流式对话。

### Rust 侧任务

- [ ] 定义与供应商无关的模型接口和能力描述。
- [ ] 实现第一家模型提供方的文本流式请求。
- [ ] 实现请求超时、取消、有限重试和错误归一化。
- [ ] 将 API Key 保存到系统安全凭据存储，只向 JS 返回是否已配置。
- [ ] 实现 Conversation、Message 和 Run 的增删查改与持久化。
- [ ] `message_send` 创建 Run 后立即返回 `runId`。
- [ ] 将文本增量通过 `run_output_delta` 推送给 JS。
- [ ] 实现 `run_get_snapshot` 和 `run_cancel`。
- [ ] 保存最终回复、耗时、模型名称和用量摘要。

### JS 侧任务

- [ ] 实现会话列表、新建、重命名和删除确认。
- [ ] 实现消息输入、消息列表、Markdown、复制和自动滚动。
- [ ] 根据增量事件更新当前助手消息。
- [ ] 实现停止生成、失败重试和断线后的快照恢复。
- [ ] 实现模型设置页和连接测试。
- [ ] API Key 仅支持覆盖或删除，不展示原始值。
- [ ] 支持通过文件选择器添加附件引用，暂不自动读取内容。

### 测试与验收

- [ ] 正常流式回复不会重复或丢失最终文本。
- [ ] 用户取消后模型请求停止，Run 进入 `cancelled`。
- [ ] 模型超时、限流和认证失败均有可理解的错误提示。
- [ ] 重启应用后可以打开历史会话。
- [ ] 事件监听暂时中断后可通过快照恢复正确状态。

**出口条件：** 完成“配置模型 → 新建会话 → 流式问答 → 取消/重试 → 重启后恢复”的闭环。

## 阶段 2：Agent Runtime 与只读桌面工具

**目标：** Agent 能安全地观察桌面环境，但还不能修改用户文件。

### Rust 侧任务

- [ ] 实现 Agent 主循环：请求模型、解析工具调用、执行工具、回传结果、生成最终答复。
- [ ] 实现 Run 状态机和合法状态转换校验。
- [ ] 实现工具注册表、输入 Schema、参数校验、结果封装和权限等级。
- [ ] 加入最大步骤数、重复调用检测、工具超时、输出截断和取消传播。
- [ ] 实现只读工具：列出目录、搜索文件、读取元信息、读取受支持文本、获取时间和系统摘要。
- [ ] 实现动作工具：使用默认应用打开文件、目录或网页。
- [ ] 实现按用户动作触发的剪贴板读取。
- [ ] 对路径进行规范化、存在性检查和敏感目录限制。
- [ ] 保存每次 Tool Call 的参数摘要、状态、耗时和结果摘要。

### JS 侧任务

- [ ] 实现 Run 状态和任务步骤展示。
- [ ] 实现 Tool Call 卡片：名称、参数摘要、进度、结果和错误。
- [ ] 实现文件选择、拖放和附件列表。
- [ ] 实现文件搜索结果、元信息和打开入口。
- [ ] 实现剪贴板读取前的显式用户触发交互。
- [ ] 实现正在执行、等待用户、完成、失败和取消状态。
- [ ] 提供结果文件或目录的“在系统中显示”入口。

### 测试与验收

- [ ] Agent 可以找到下载目录中指定条件的文件并汇总结果。
- [ ] Agent 可以读取用户明确选择的文本文件并总结。
- [ ] Agent 不可读取受限目录和超出大小限制的文件。
- [ ] 重复工具调用达到阈值后停止并返回可诊断错误。
- [ ] 取消 Run 会中止尚未完成的工具。
- [ ] UI 不展示模型隐藏推理，只展示计划、动作和结果。

**出口条件：** 完成“自然语言请求 → Agent 调用只读工具 → 用户看到执行过程 → 返回可验证结果”的闭环。

## 阶段 3：授权与文件变更

**目标：** Agent 可以在具体、可验证的授权之后修改文件系统。

### Rust 侧任务

- [ ] 实现风险分级和工具授权策略。
- [ ] 实现 `ApprovalRequest` 创建、过期、拒绝和单次消费。
- [ ] 授权绑定 Tool Call 与参数摘要，执行前再次校验目标未变化。
- [ ] 实现文件操作预览，返回来源、目标、数量、冲突和可撤销性。
- [ ] 实现创建目录/文本文件、复制、移动和重命名。
- [ ] 实现删除到系统回收站，禁止永久删除。
- [ ] 实现重名冲突策略：跳过、改名或覆盖；覆盖必须单独确认。
- [ ] 限制单次批量操作数量，并记录逐项执行结果。
- [ ] 对所有副作用操作写入审计记录。
- [ ] 用户拒绝或授权过期后确保零副作用。

### JS 侧任务

- [ ] 实现全局授权队列和授权弹窗。
- [ ] 展示动作、风险、原因、源/目标、文件数量和可撤销性。
- [ ] 实现本次允许、拒绝、修改参数和查看完整清单。
- [ ] 实现批量操作预览和冲突处理界面。
- [ ] 实现逐项进度、成功项、跳过项和失败项汇总。
- [ ] 授权过期时禁用旧按钮并刷新 Run 状态。
- [ ] 任务结束后展示变更摘要和快捷打开入口。

### 测试与验收

- [ ] 未授权、伪造授权、重复使用授权均不能执行副作用操作。
- [ ] 用户拒绝后文件系统无变化。
- [ ] 操作对象在预览后变化时，旧授权失效并要求重新确认。
- [ ] 批量移动部分失败时能准确汇报每一项状态。
- [ ] 删除后的文件可以从系统回收站恢复。
- [ ] JS 被绕过直接调用危险 Command 时，Rust 仍拒绝执行。

**出口条件：** Agent 可以安全完成一次批量文件整理，且执行前可预览、执行中可取消、执行后可审计。

## 阶段 4：提醒、通知与桌面体验

**目标：** Yukin 从前台聊天工具变成可持续使用的桌面助手。

### Rust 侧任务

- [ ] 实现一次性提醒和周期提醒的数据模型。
- [ ] 实现创建、查询、更新、启用、禁用和删除。
- [ ] 实现下次触发时间计算、时区处理和周期规则校验。
- [ ] 实现到期调度、桌面通知和触发历史记录。
- [ ] 实现应用重启后的提醒恢复。
- [ ] 定义系统休眠期间错过提醒的补发策略。
- [ ] 实现托盘菜单、单实例、窗口显示/隐藏。
- [ ] 实现可配置的全局快捷键。
- [ ] 通知点击后向 JS 发送事件并定位原始会话或提醒。

### JS 侧任务

- [ ] 实现自然语言创建提醒后的确认卡片。
- [ ] 实现提醒列表、编辑、启停和删除确认。
- [ ] 明确展示本地时区和下一次触发时间。
- [ ] 实现任务中心：运行中、等待授权、最近完成和失败任务。
- [ ] 实现快捷输入窗口或紧凑唤起模式。
- [ ] 实现通知点击后的会话/提醒定位。
- [ ] 实现托盘和快捷键相关设置。

### 测试与验收

- [ ] 创建一分钟后的提醒可以准时收到系统通知。
- [ ] 周期提醒的下一次触发时间计算正确。
- [ ] 重启应用后提醒仍存在并会触发。
- [ ] 系统休眠恢复后按照既定策略处理错过提醒。
- [ ] 快捷键可以显示已有窗口，不启动重复实例。
- [ ] V1 定时任务只能通知，不能静默执行高风险工具。

**出口条件：** 完成“自然语言创建提醒 → 后台持久化 → 到期通知 → 点击回到任务”的闭环。

## 5. 推荐执行顺序与依赖

```text
阶段 0 协议与基础
  └─ 阶段 1 模型与会话
       └─ 阶段 2 Agent 与只读工具
            ├─ 阶段 3 授权与文件变更
            └─ 阶段 4 提醒与桌面体验
                 └─ 阶段 5 Alpha 收口
```

- 阶段 0 完成前，不并行开发正式业务页面和危险工具。
- 阶段 2 的只读工具稳定后，再开放阶段 3 的副作用工具。
- 阶段 3 与阶段 4 可在阶段 2 完成后并行推进。
- 每个阶段必须满足出口条件后才能标记完成。

## 6. 首批垂直切片

不要先把所有后端模块或所有页面分别做完。按下列垂直切片逐个交付：

1. **流式对话切片**：输入消息 → Rust 请求模型 → Event 增量 → JS 展示 → 持久化。
2. **文件搜索切片**：自然语言请求 → Tool Call → Rust 搜索 → JS 结果卡片 → 最终总结。
3. **文件移动切片**：请求整理 → Rust 预览 → JS 授权 → Rust 执行 → JS 结果汇总。
4. **提醒切片**：自然语言创建 → Rust 持久化/调度 → 通知 → JS 定位详情。

每个切片都必须同时包含错误、取消、日志和最小测试，不把这些工作统一拖到最后。

## 7. Definition of Done

一个任务只有同时满足以下条件才算完成：

- [ ] 行为与共享协议一致，数据结构包含版本信息。
- [ ] Rust 侧完成参数、权限和状态校验。
- [ ] JS 侧包含加载、成功、空、错误和取消状态。
- [ ] 涉及副作用时存在可验证的授权或明确的免授权规则。
- [ ] 至少包含关键路径测试和一个失败路径测试。
- [ ] 日志足以定位错误，且不泄露敏感数据。
- [ ] 应用重启后数据状态符合设计。
- [ ] 用户可以看懂最终发生了什么，以及哪些操作失败。
- [ ] 构建、静态检查和相关测试通过。

## 8. V1 最终验收场景

发布 Alpha 前必须逐条通过：

1. 用户配置模型后进行多轮流式对话，取消和重试均正常。
2. 用户要求查找“下载目录最近七天的 PDF”，Agent 返回真实文件列表。
3. 用户选择若干文本文件，Agent 读取并生成摘要。
4. 用户要求把一组文件移动到新目录，Agent 先展示预览，授权后执行并汇报逐项结果。
5. 用户拒绝文件删除后，任何文件都没有变化。
6. 用户同意删除后，文件进入系统回收站而非永久消失。
7. 用户创建“30 分钟后提醒我休息”，应用重启后仍能触发通知。
8. 用户通过快捷键唤起应用，且不会产生重复实例。
9. 模型断网、授权过期、目标文件变化、部分文件操作失败时，状态和提示均正确。
10. 用户可以导出脱敏诊断信息并清除 Yukin 的本地数据。

## 9. V1 之后再评估

- 浏览器页面交互和网页登录态操作。
- PDF、Office、OCR 等复杂文档处理。
