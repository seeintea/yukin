# Yukin 后续功能开发计划

> 创建时间：2026-08-19（Asia/Shanghai）
>
> 状态：阶段 1、阶段 2 已实施；阶段 3 已实现，待桌面端真实模型联调验收；阶段 4 切片 1、2 已实现
>
> 前置成果：多轮对话、Agent Run、Tool 审批、内置 Skills、设置页和 Provider CRUD 已完成。

## 1. 目标

按照“小步快走”的方式，从当前聊天与设置能力继续推进 V1：

1. 补齐 Provider 配置验证闭环。
2. 补齐会话重命名和删除能力。
3. 接入用户明确选择的文本文件，完成第一个真实桌面只读能力。
4. 在安全边界稳定后扩展文件搜索、元信息和打开能力。

推荐实施顺序：

```text
Provider 连接测试
  → 会话重命名与删除
  → 选择并读取文本文件
  → 文件搜索、元信息与打开
  → 文件变更与授权
  → 提醒和通知
```

## 2. 实施原则

- 每个阶段形成一个可以独立验收的前后端闭环。
- Rust 继续作为模型凭据、文件路径、权限和持久状态的权威来源。
- 前端所有后端 API 通过 React Query 查询或 Mutation 管理。
- 优先复用现有 shadcn 组件；开始 UI 实现前先确认缺失组件，由用户手动安装。
- 不为后续阶段提前建立空模块或通用框架。
- 文件能力先只读、后写入；副作用操作继续经过 Tool Registry 和审批。
- API Key 不返回前端、不写入日志，也不进入 Conversation、Message 或 Run。

## 3. 阶段 1：Provider 连接测试

### 目标

用户可以在设置页验证 Provider、API Key、服务地址和模型是否能够正常完成请求，不必通过发送正式聊天消息试错。

### 协议

```ts
interface TestConnectionRequest {
  providerId: string;
  modelId: string;
}

interface TestConnectionResponse {
  modelId: string;
  latencyMs: number;
}
```

错误继续使用现有结构化 `AppError`，区分认证失败、限流、超时、请求错误和上游服务错误。

### Rust

- [x] 新增 `model_provider_test_connection` Command。
- [x] Command 只接收请求并调用具体工作流，不直接读取凭据或调用模型。
- [x] 工作流根据 `providerId` 读取运行配置和系统凭据。
- [x] 校验 `modelId` 属于该 Provider 当前支持的模型。
- [x] 通过现有 Provider Adapter 发起一次最小非流式请求。
- [x] 设置独立的短超时，不创建 Conversation、Message、Run 或 Tool Call。
- [x] 返回实际模型和请求耗时，不返回响应正文、API Key 或底层请求头。
- [x] 保证诊断日志不包含凭据和完整响应正文。

连接测试会产生一次极小的真实模型请求，可能消耗少量 Token；UI 中需要明确说明。

### React

- [x] 在 Provider 行操作菜单增加“测试连接”。
- [x] 使用 Dialog 展示当前 Provider 和模型选择器。
- [x] 模型选项来自 Provider Preset Query。
- [x] 使用 React Query Mutation 调用测试 Command。
- [x] 测试期间禁用重复提交和关闭操作。
- [x] 成功后展示模型名称和耗时。
- [x] 失败时通过 Toast 和 Dialog 内状态展示可理解的错误。

### 测试与验收

- [x] 正确配置可以完成连接测试。
- [x] 错误 API Key 返回认证错误。
- [x] 无效地址、超时、限流和上游错误有稳定错误码。
- [x] 不产生任何 Conversation、Message 或 Run 记录。
- [x] API Key 不出现在 IPC、日志和测试返回值中。

### 出口条件

用户在 Provider 设置页即可确认配置有效，并能区分常见失败原因。

## 4. 阶段 2：会话重命名与删除

### 目标

用户可以管理逐渐积累的历史会话，并且删除当前会话后仍能稳定落到可用页面。

### 协议

```ts
interface ConversationRenameRequest {
  id: string;
  title: string;
}

interface ConversationDeleteRequest {
  id: string;
}
```

### Rust

- [x] 新增 `conversation_rename` 和 `conversation_delete` Command。
- [x] 标题去除首尾空白并限制合理长度。
- [x] Storage 返回更新后的 Conversation。
- [x] 删除 Conversation 时通过原子删除和外键级联清理关联记录。
- [x] Conversation 存在活动 Run 时拒绝删除并返回稳定错误。
- [x] 为重命名、删除和活动 Run 冲突增加测试。

### React

- [x] 在会话列表项增加行操作菜单。
- [x] 使用 Dialog 完成重命名。
- [x] 使用 Alert Dialog 完成删除确认。
- [x] 使用 React Query Mutation 更新或失效 Conversation 缓存。
- [x] 删除非当前会话后保持当前页面不变。
- [x] 删除当前会话后切换到下一条；没有剩余会话时自动创建新会话。
- [x] Mutation 进行中禁止重复操作。

### 测试与验收

- [x] 重命名后 Sidebar 和当前会话缓存保持一致。
- [x] 删除会话后关联消息和 Run 不再可查询。
- [x] 活动 Run 所属会话不能删除。
- [x] 删除当前或最后一个会话不会出现空白页和无效路由参数。

### 出口条件

用户可以安全整理历史会话，切换、重命名和删除后的路由与缓存始终一致。

## 5. 阶段 3：选择并读取文本文件

### 目标

完成第一个面向真实桌面场景的只读闭环：用户明确选择文本文件，Agent 读取后进行总结或问答。

### 范围

第一版只支持用户主动选择的单个 UTF-8 文本文件，不支持目录、拖放、自动搜索、二进制文件或任意路径读取。

### Rust

- [x] 定义最小文件引用协议，只向前端返回展示所需元数据。
- [x] 通过系统文件选择器获得用户明确选择的文件。
- [x] 在 Rust 保存本次选择对应的受限文件引用，避免模型提交任意路径。
- [x] 实现只读取已授权引用的文本工具。
- [x] 校验文件存在性、类型、编码和大小上限。
- [x] 限制工具输出大小，并对读取错误返回稳定错误码。
- [x] Run 取消时中止尚未完成的读取。
- [x] Tool Call 记录文件名和结果摘要，不持久化完整文件正文。

### React

- [x] 在聊天输入区增加附件选择入口。
- [x] 展示已选择文件的名称和大小，并允许发送前移除。
- [x] 将受限文件引用随 Run Start Request 提交。
- [x] Tool Call 卡片展示正在读取、完成或失败状态。
- [x] 消息历史只展示附件元数据，不把本地绝对路径作为普通文本暴露。

### 安全规则

- 模型不能通过工具参数读取用户未选择的路径。
- 符号链接、路径变化和文件被替换时需要重新校验。
- 超出大小上限、非文本或解码失败的文件不得进入模型上下文。
- 文件内容不写入日志和 Tool Call 结果摘要。

### 测试与验收

- [ ] 用户选择正常文本文件后，Agent 可以总结其内容。
- [x] 未授权路径、超大文件、二进制文件和无效编码被拒绝。
- [x] 文件在选择后发生变化时能够被检测并安全终止。
- [ ] 取消 Run 会停止读取或后续模型请求。
- [x] IPC、日志和历史消息不泄露不必要的绝对路径与完整文件内容。

### 出口条件

完成“选择文本文件 → Agent 读取 → 展示 Tool Call → 返回总结”的安全只读闭环。

## 6. 阶段 4：文件搜索、元信息与打开

### 目标

在阶段 3 的路径与读取安全边界稳定后，让 Agent 能在用户允许的范围内查找和打开文件。

### 实施切片

1. [x] 列出用户选择目录的直接子项。
2. [x] 按文件名和基础条件搜索文件。
3. [ ] 读取文件大小、修改时间和类型等元信息。
4. [ ] 使用系统默认应用打开文件，或在文件管理器中显示目标。

### Rust

- [x] 引入目录范围授权，所有搜索限制在已授权根目录内。
- [ ] 实现路径规范化、符号链接处理和敏感目录限制。
- [x] 限制搜索深度、结果数量、运行时间和输出大小。
- [ ] 打开文件或目录使用固定系统能力，不接受任意 Shell 命令。
- [ ] 持久化 Tool Call 状态和结果摘要。

### React

- [x] 展示搜索范围、查询条件和结果数量。
- [x] Tool Call 卡片展示有限的文件结果摘要。
- [ ] 提供“打开”和“在系统中显示”操作。
- [ ] 对截断、超时和权限不足提供明确提示。

### 出口条件

用户可以通过自然语言在明确授权的目录内查找文件，并打开或定位结果。

## 7. 后续阶段

完成上述四个阶段后，再分别建立独立计划：

- 文件创建、复制、移动、重命名和移入回收站。
- 文件操作预览、冲突处理、批量结果和审计记录。
- 一次性与周期提醒、系统通知和提醒管理页面。
- 托盘、单实例、全局快捷键和紧凑输入窗口。
- 数据导出、诊断、首次启动引导和 Alpha 发布准备。

暂不推进：自动 Skill 路由、完整 Skill 编辑器、插件市场、多 Agent、长期记忆、云同步、任意 Shell 和任意应用 UI 自动化。

## 8. 建议提交粒度

每个阶段至少拆为独立提交，避免将多个垂直切片混在一起：

```text
feat(model-provider): add connection test workflow
feat(conversation): add rename and delete operations
feat(files): add selected text file reading
feat(files): add scoped file search and open tools
```

每个提交前运行与风险相称的检查：

- Rust：`cargo fmt --all -- --check`、`cargo test`、适用时执行 Clippy。
- React：`pnpm oxc`、`pnpm build`。
- Migration：只能新增编号，不修改已经应用的历史 Migration。
