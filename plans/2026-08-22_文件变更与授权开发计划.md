# Yukin 文件变更与授权开发计划

> 创建时间：2026-08-22（Asia/Shanghai）
>
> 状态：切片 1、2 已实现，待桌面端真实模型联调验收
>
> 前置成果：受限目录列出、搜索、元信息、默认应用打开和文件管理器定位已完成并通过真实模型联调。

## 1. 目标

让 Agent 在用户明确授权的目录内执行有限、可预览、可审批的文件变更，并保证拒绝、过期或目标变化时不产生副作用。

实施顺序：

1. [x] 在授权目录根部创建新的 UTF-8 文本文件。
2. [x] 在授权目录内创建子目录。
3. [ ] 复制文件和目录。
4. [ ] 移动与重命名文件和目录。
5. [ ] 将文件和目录移入系统回收站。
6. [ ] 补齐冲突处理、批量结果和审计汇总。

## 2. 安全边界

- 所有目标必须来自当前 Run 的目录授权或已生成的条目引用。
- 模型和前端不得提交绝对路径，Rust 始终是路径与授权的权威来源。
- 所有文件变更工具使用 `write` 风险级别并强制逐次审批。
- 审批绑定 Tool Call、完整参数摘要和参数摘要哈希；执行前重新校验授权范围与目标状态。
- 第一版不覆盖已有目标，不接受任意 Shell，不跟随符号链接。
- 拒绝、审批过期、Run 取消和执行前校验失败必须保持零副作用。
- Tool Call 记录操作参数与结果摘要，不记录本地绝对路径。

## 3. 切片 1：创建文本文件

### 范围

- 只允许在用户选择目录的根部创建单个 `.txt` 文件。
- 文件名必须是单一普通文件名，不允许目录分隔符、隐藏文件或其他扩展名。
- 内容必须是 UTF-8 字符串且不超过 32 KiB。
- 使用原子 `create_new` 语义，已有同名目标时失败，不覆盖、不自动改名。

### Rust

- [x] 在目录授权层实现执行前根目录复验和安全文件创建。
- [x] 新增 `create_text_file_in_selected_directory` Agent 工具。
- [x] 工具仅在 Run 携带目录授权时可用，并强制用户审批。
- [x] 创建结果生成条目引用，支持后续读取元信息、打开和定位。
- [x] Tool Call 结果摘要不包含文件内容和绝对路径。
- [x] 覆盖成功、同名冲突、无效文件名、超限内容和授权失效测试。

### React

- [x] 审批卡片展示文件名、内容预览和创建范围。
- [x] 完成后展示新文件，并提供“打开”和“在系统中显示”操作。
- [x] 同名冲突、权限不足和授权失效提供明确提示。

### 出口条件

用户可以通过自然语言在明确授权的目录中创建新的文本文件；未批准、目标冲突或授权失效时文件系统不发生变化。

## 4. 切片 2：创建子目录

- 使用单目录创建语义，已有同名文件或目录时失败，不合并、不覆盖。

- [x] 创建结果生成目录条目引用，支持后续打开和定位。
- [x] 覆盖成功、同名冲突、无效名称和未授权引用测试。

### React

- [x] 同名冲突、无效名称、权限不足和授权失效提供明确提示。

### 出口条件

用户可以通过自然语言在明确授权的目录中创建直接子目录；未批准、目标冲突或授权失效时文件系统不发生变化。

## 5. 切片 3：复制文件和目录

### 范围

- 源条目必须来自当前授权目录的列出或搜索结果，使用 opaque 引用与相对路径共同绑定。
- 目标仅限同一授权目录的根部或已列出/搜索的子目录，副本名称必须显式提供。
- 不覆盖、不合并、不自动改名；目录复制最多 100 个条目、8 层、16 MiB。
- 符号链接和特殊文件不复制；目录不能复制到自身或其后代目录。
- 失败或取消时清理本次创建的未完成目标。

### Rust

- [x] 在目录授权层实现文件和目录预检、范围复验与安全复制。
- [x] 新增 `copy_directory_entry` Agent 工具并强制用户审批。
- [x] 源和目标目录均绑定 opaque 引用与相对路径，不接收本地绝对路径。
- [x] 使用不覆盖语义创建目标，并为失败或取消配置清理守卫。
- [x] 复制结果注册为新条目引用，可继续读取元信息、打开和定位。
- [x] 覆盖文件、嵌套目录、同名冲突、自身后代目标、范围上限与未审批测试。

### React

- [x] 审批卡片明确展示来源、目标目录和副本名称。
- [x] 完成后展示条目数、总字节数和新条目操作入口。
- [x] 同名冲突、无效目标、自身后代目标和范围超限提供明确提示。

### 出口条件

用户可以在同一明确授权目录范围内复制单个已列出或搜索的文件或目录；未批准、目标冲突、范围超限、授权失效、失败或取消时不保留新目标。

## 6. 切片 4：移动与重命名

### 范围

- 源条目必须来自当前授权目录的列出或搜索结果，使用 opaque 引用与相对路径共同绑定。
- 目标仅限同一授权目录的根部或已列出/搜索的子目录，新名称必须显式提供。
- 不覆盖、不合并、不自动改名；目录不能移动到自身或其后代目录。
- 移动成功后原条目及其后代的旧引用全部失效，新位置生成新引用。

### Rust

- [x] 在目录授权层实现执行前源、目标目录和授权根复验。
- [x] 新增 `move_directory_entry` Agent 工具并强制用户审批。
- [x] 使用单次文件系统重命名完成同一授权范围内的移动或改名。
- [x] 移动后注销原条目树的旧引用，并注册新位置引用。
- [x] 覆盖文件、目录移动、改名、同名冲突、自身后代目标、旧引用失效和未审批测试。

### React

- [x] 审批卡片明确展示原位置、新目标目录和新名称。
- [x] 完成后展示前后相对路径及新条目操作入口。
- [x] 同名冲突、无效名称、自身后代目标和授权失效提供明确提示。

### 出口条件

用户可以在同一明确授权目录范围内移动或重命名单个已列出或搜索的文件或目录；未批准、目标冲突或授权失效时原条目不变，成功后旧引用不可继续使用。

## 7. 切片 5：移入系统回收站

### 范围

- 只允许处理当前授权目录中已列出或搜索的单个文件或目录。
- 操作必须移入操作系统回收站，不提供永久删除能力。
- 成功后目标条目及其后代的旧引用全部失效；失败时保留引用和原条目。

### Rust

- [x] 引入跨平台系统回收站能力，不使用永久删除 API。
- [x] 新增 `trash_directory_entry` Agent 工具并强制用户审批。
- [x] 执行前复验授权根、opaque 引用、相对路径和条目类型。
- [x] 将阻塞的系统回收站调用放入后台任务，避免阻塞异步运行时。
- [x] 成功后注销条目树引用，失败时保留原状态。
- [x] 覆盖成功、失败、后代引用失效、无效引用和未审批测试。

### React

- [x] 审批卡片明确展示将移入系统回收站的相对路径。
- [x] 明确提示该操作不会永久删除，并可通过系统回收站恢复。
- [x] 完成和失败状态提供清晰反馈。

### 出口条件

用户可以将明确授权的单个文件或目录移入系统回收站；未批准或系统操作失败时原条目保持不变，任何流程都不提供永久删除。

## 8. 后续切片原则

- 每个切片独立形成协议、Rust、React、测试和真实桌面验收闭环。
- 复制、移动和删除类操作先返回完整预览，再请求批准，批准后重新校验目标。
- 删除只允许移入系统回收站，不实现永久删除。
- 批量操作进入实施时再增加逐项结果与冲突策略，不提前建立通用批处理框架。
